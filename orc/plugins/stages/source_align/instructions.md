# Source Align

Synchronises between 1 and 16 input sources so that output frame 0 corresponds to the same physical disc position across all inputs. Without alignment, independent captures may start at different tracks, making pixel-level stacking impossible. Source Align applies a per-input frame offset — padding the start of the later-starting sources, or trimming the start of the earlier ones — from an alignment map that its Source Alignment Analysis tool works out from the discs' VBI picture numbers or CLV timecodes.

## When to use

Use Source Align whenever you connect more than one source to a Stacker stage and the captures did not start at exactly the same disc position. Example: three captures of the same LaserDisc that each began playing slightly earlier or later — map each with a Frame Map, connect all three to Source Align, run the Source Alignment Analysis tool, then connect the aligned outputs to Stacker.

## What it does

The stage applies the per-input frame offsets given in `alignmentMap`; it does not read the VBI itself. The offsets are worked out by the Source Alignment Analysis tool (below), which reads the VBI picture numbers of CAV discs or the timecodes of CLV discs, or can be entered by hand. Each input named in the map produces one output, and the outputs are frame-aligned with one another. An input the map does not name is left out of the outputs.

With `alignmentMap` empty the stage is not configured (red status): a single input passes through unchanged, but with two or more inputs the stage fails and asks for the map to be generated.

In `pad_for_alignment` mode the leading padding is followed by tail padding: every output is padded at the end to the length of the longest one, so all outputs have the same frame count and a stacker downstream keeps the pictures that only the longer captures carry. Padding frames have the source's full frame geometry, including the two extra samples PAL carries on lines 312 and 624, and are marked as padding so the stacker ignores them. In `first_common_frame` mode nothing is padded.

Audio follows the alignment. Every audio channel pair remaps per frame: trimmed sources serve their audio from the shifted frame IDs, and padded sources carry silence on the leading and trailing padding frames. Each output frame always carries the exact per-frame sample count required by its position in the output timeline (constant on PAL; alternating per the SMPTE 272M five-frame sequence on NTSC/PAL-M), so an offset that breaks the NTSC/PAL-M sequence phase trims or silence-pads each shifted frame's audio by a single trailing stereo pair. Offsets that preserve the phase (multiples of 5) — and all PAL offsets — are sample-exact. Sample values and rates are never changed.

## Parameters

### alignmentMode (string)
How the offsets in `alignmentMap` are applied. `pad_for_alignment` prepends that many padding frames to each input, then pads every output at the tail to the longest one. `first_common_frame` drops that many leading frames from each input and leaves the tails as they are. Default: `pad_for_alignment`.

### alignmentMap (string)
Per-input frame offsets. Format: `INPUT_ID+OFFSET` entries separated by commas, where INPUT_ID is the 1-based input number and OFFSET is a number of frames: the padding frames prepended to that input in `pad_for_alignment` mode, or the leading frames dropped from it in `first_common_frame` mode. Example: `1+2, 2+2, 3+1, 4+1`. Default: `""` (not configured). Use the Source Alignment Analysis tool to generate this value.

## Tools

### Source Alignment Analysis
Analyses all connected sources and determines the optimal per-input offset so that every source starts at the same disc position. Choose an alignment mode: `pad_for_alignment` prepends synthetic padding frames so all sources start from the earliest picture available across all inputs (no frames are lost). In this mode each source is placed in frames, by the frames at which it and the others read the same pictures (the median offset over the pictures they share, at least three), so a source that opens on a lead-in frame or an unreadable frame, or carries one corrupt early number, still lines up with the others. Placing by frames matters on film with 3:2 pulldown, where the disc numbers four pictures in every five frames and a source starting eight pictures late starts ten frames late. A source that shares no pictures with any other in the frames scanned is placed by its picture numbers alone, a picture per frame. A source with no picture numbers at all cannot be placed: it is left out of the map, and so out of the stage's outputs, and the report names it. `first_common_frame` trims all sources to the first VBI frame that exists in every input (may discard unique leading content). The tool writes the resulting offset map to `alignmentMap` automatically. The analysis can be cancelled at any time from the tool dialog. Available for LaserDisc sources only. Invoke from the Stage Tools menu.

After placing the sources, the analysis compares them on up to 16 frames of the same picture taken across the stretch every source covers, and adds a **Capture comparison** to its report. The frames are spread as the Stacker spreads the frames it groups its inputs from, so for the same sources in the same order the two find the same pressings and families. The noise figures are averages over those frames; the Stacker measures them again for every 500 frames, and on a side that mixes flat stills with detailed pictures its per-segment figures spread a couple of codes either side of the comparison's.

- Each source's noise in 10-bit codes, measured after shifting it onto the first source's sample grid and skipping flagged samples. It is measured as the Stacker's Weighted mode measures it: on flat areas of the picture, each block about its own mean, so that a source whose gain or level differs from the others' is not counted as noisy.
- The luma **levels** of any source more than 1 % in gain or 2 codes in level from the picture common to all of them. Players and decodes differ like this.
- The **pressings**. Discs of one pressing carry the noise recorded into its stamper, which only averages out across pressings. The report groups the sources by pressing, using the same measurement as the Stacker's Weighted mode (A {1, 2, 3}, B {4, 5}), and gives the share of each disc's noise that is its pressing's. Stampers are made from mothers, and where pressings share a mother a **Families** line names them and gives the share of their discs' noise that is the family's; the Stacker counts each family about once. If all the sources come from one pressing, it says that stacking them cannot remove the stamper's noise. Pressings can only be told apart with 4 or more sources. A source alone in its group is either the only disc of its pressing or much noisier than the rest; the two look the same.
- Each source's **response at 5–6 MHz** against the typical source's, with 3 or more sources. Discs of one pressing or family share their noise in that band, which reads as response, so where there are enough families to settle it the response is measured only between sources of different families. A source below 0.75 is reported as soft in a warning: its capture chain loses fine detail, and stacking it with sharper sources blurs the result slightly.
- If no grouping into pressings and families explains the sources' differences, a **Noise model** line says so and names the pair furthest from it. Each noise figure is then the source's spread against the others, no response is given, and the Stacker stacks such sources equally.
- **What each source adds**: the noise σ the model predicts for a Weighted stack of every source, then, most first, the σ the stack would have without each source and that source's share of the weight. Read this, not each source's own noise, when choosing which discs to leave out. The discs that share the noise recorded into one stamper form a *stamper group* (the groups the Pressings line letters). A disc alone in its stamper group reads noisier than the rest, yet it often adds the most, because no other disc carries its noise. Stamper groups are groups of shared noise, not versions of the content, so Weighted needs no one pressing chosen for the video; which pressing to take still matters for EFM data. When the noise model is not trusted, the figures describe the equal stack the Stacker then makes.

- Each source's **edge tails** on the VITS white bar (PAL line 19, NTSC and PAL-M line 20), averaged over the bar lines of 32 frames spread across the source: the share of the rising and of the falling edge that settles slowly after the edge's fast part, and its time constant. A tail the same on every capture comes from the decoder and is its to correct; one that differs between players or decodes is a property of the capture. Tails faster than 0.3 µs are not resolved; the time constant is not given for a tail under 1 %.
- The **picture band**, with a trusted grouping into two or more stamper families: the coherence between captures of different families, which share the picture and nothing else, falls to a floor where the picture ends. Luma and chroma are separated by a vertical comb over three lines of a field (two lines apart on PAL and PAL-M, adjacent on NTSC). The report gives the frequency where each falls to within 0.05 of its floor (the lowest it falls, over 0.5 MHz) and stays there for 0.5 MHz: luma from 1 MHz up, chroma from the subcarrier up, and below 7 MHz on PAL or 6.2 MHz on NTSC and PAL-M, short of the decode's own band edge. Above the luma cutoff the captures carry only noise. Where every pressing comes from one mother, the mother's noise is common to all of them above the picture and no cutoff is found; with two pressings the comparison cannot tell such pressings from independent ones.

Then the analysis checks each source's **picture numbers against its content**. Source Align places frames by the picture numbers their VBI carries, so a capture whose numbers are off by one holds, at each output frame, the neighbouring picture; stacked, it blends that picture in with its chroma in another phase. In 24 windows across the source covering the most frames, the check takes frames whose picture differs from both neighbours' (on a still every offset matches), and compares each other source's frames two either side with it, on a luma map of 8-sample by 2-line block means, which chroma averages out of. Where a source's best match is clearly closer than any other, that is its offset; where none comes within half the reference's own change from one frame to the next, its frames hold none of the others' pictures. A change of offset between windows is narrowed to the frame where the content allows it. Each source is then judged against what most sources read, so a reference that is itself off is the one reported. A source that differs gets a warning naming the output frames and the offset; one off by the same offset everywhere gets the alignment map that would correct it, which is not applied.

The comparison and the check only report; neither changes the alignment map.

### From the command line
`orc-cli tools run <project> source_alignment --node <this stage> --apply` runs the analysis and writes `alignmentMap` and `alignmentMode`; without `--apply` it only reports them. With `--json`, the capture comparison's figures come as data as well as text: one `info` item per input whose `data` holds that source's figures, and the comparison's own figures among the `statistics`. The CLI user guide's multi-disc stacking page lists the keys. Choose the mode with `--param alignmentMode=first_common_frame` or `pad_for_alignment`. Map each disc with the Disc Mapper first. The command refuses a stack whose sources mix `.tbc` and `.cvbs` captures (exit code 5); take all the discs of one stack from the same capture format.

### Refreshing from the command line
The Source Alignment Analysis dialog has a **Use this tool when refreshing from the CLI** option. Tick it and press **Apply to Stage** or **OK** to record in the project that `orc-cli tools refresh` runs the analysis for this stage, with the alignment mode set in the dialog; save the project to keep it. `orc-cli tools refresh-config <project> <this stage> source_alignment` makes the same choice from a script. A refresh maps every disc's Frame Map first, so the alignment always reads the new frame lists.

## Status Indicator

The coloured dot in the top-right corner of the node shows its configuration status.

| Colour | Meaning |
|--------|---------|
| Green | `alignmentMap` is set. |
| Red | `alignmentMap` is empty. Run the Source Alignment Analysis tool, or enter the map by hand. |

Parameters can be set via **Edit Parameters...** in the node context menu. Some stages also provide interactive stage tools (listed under **Tools** above) that set parameters directly from within the tool.
